# riffle

線上牌桌。大老二（2~4 人，五條規則各自可開關）、德州撲克（2~9 人）、大富翁（2~6 人，
完整規則含蓋房、抵押、機會命運、監獄、拍賣與交易）、貪吃蛇（2~4 人，即時制）
與台灣麻將（固定 4 人，缺人自動補電腦代打）共用同一層房間邏輯：
開房、用房號加入、觀戰，大廳與房間各有獨立聊天室。伺服器持有權威狀態，
所有出牌、下注、棋步與吃碰槓胡都在後端驗證過才算數。

介面有三套可即時切換的外觀，其中兩套長得像編輯器與終端機，另附老闆鍵與失焦自動遮蔽。

## 快速開始

```bash
npm install
npm run dev
```

開 http://localhost:5173 ，輸入暱稱就能開房。
**要多開幾個玩家，直接開新分頁即可** —— 身分存在 `sessionStorage`，每個分頁是獨立玩家，
但重新整理（F5）還是同一個人，會接回原本的座位與手牌。

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 同時啟動後端 (3005) 與前端 dev server (5173) |
| `npm test` | 規則引擎與遊戲流程的單元測試 |
| `npm run typecheck` | 三個套件的型別檢查（沒有 linter，這個就是關卡） |
| `npm run build` | 打包前端到 `client/dist` |
| `npm run serve` | 打包後用單一服務跑在 `0.0.0.0:80` |

## 下載發行版

不想自己 build 的話，[Releases](https://github.com/SP42K/riffle/releases) 有打包好的 zip，
前端已經是打包產物，解壓後只要裝執行期相依就能跑：

```bash
npm ci --omit=dev
npm start -w server -- --port 8080
```

需要 Node 22 以上。解壓出來的目錄結構不要動 —— 後端是照相對路徑找 `client/dist` 的。

## 開在區網 / 換連接埠

`npm run serve` 會先打包前端，再讓後端綁 `0.0.0.0:80`，同一個網址就同時提供 API 與前端。
啟動時會把可用的區網位址印出來，直接把 `http://192.168.x.x` 給同網段的人就能連。

連接埠與網卡都可以改，命令列參數優先於環境變數：

```bash
npm start -w server -- --port 8080        # 換埠
npm start -w server -- --host 127.0.0.1   # 只開放本機
npm run dev -w client -- --port 80        # dev server 也可以換埠（Vite 原生旗標）
```

只要 `client/dist` 存在，後端就會一併吐出前端；沒打包過就只有 API，前端請走 `npm run dev`。

> Windows 的 80 埠常被 IIS 或 http.sys 占著。若出現 `EADDRINUSE` 就換一個埠，
> `EACCES` 則需要用系統管理員身分執行。

## 用 Docker 跑

| 跑法 | 指令 | 用途 |
|---|---|---|
| 直接執行（現況，不變） | `npm run serve` | 區網開一局、release zip |
| 容器全套 | `docker build -t riffle .` | 單一容器同源，等同 `npm run serve` |
| 容器只跑 API | `docker build --target server .` | 前端另外部署（例如 Vercel），後端在常駐容器 |

```bash
docker build -t riffle .            # 全套（前端 + API）
docker run -p 8080:3001 riffle

docker build --target server -t riffle-api .   # 只跑 API
docker run -p 3001:3001 -e CORS_ORIGIN=https://xxx.vercel.app riffle-api
```

狀態全在記憶體裡（rooms / sessions / playerRoom），所以只能跑單一 instance，不要加
replicas 或開 autoscaling。前後端分家部署時才需要下面兩個設定，**兩個的時機不一樣**：

- `CORS_ORIGIN`（執行期環境變數）：後端允許的前端來源，逗號分隔；沒設就沿用同源部署的
  寬鬆預設。有設卻解析不出任何來源（例如只打了逗號）伺服器會直接不啟動，免得靜靜退回全開。
- `VITE_SERVER_URL`（**build 參數**）：前端要打的後端網域；沒設就走同源。vite 是在打包當下
  把它寫死進 bundle 的，執行期再設沒有作用，所以要在 build 時帶：

  ```bash
  docker build --build-arg VITE_SERVER_URL=https://api.example.com -t riffle .
  ```

  前端上 Vercel 時同理 —— 在 Vercel 的環境變數頁設好，它是在那邊 build 的。

> `CORS_ORIGIN` 擋的是瀏覽器發起的跨站連線（polling 與 WebSocket 升級都會驗）。
> 這個服務本來就沒有帳號密碼，白名單不等於存取控制，別拿它當權限用。

## 部署到 Vercel + Render

前端（`client/dist`）上 Vercel，後端上 Render 的常駐服務，兩個設定檔都在 repo root：
`vercel.json` 與 `render.yaml`。遊戲邏輯完全不動。權衡與其他方案見
[`docs/deployment.md`](docs/deployment.md)。

第一次上線是雞生蛋順序，一定要來回兩趟：

1. Render 接這個 repo 開 Web Service（會讀 `render.yaml`），拿到 `https://xxx.onrender.com`。
2. Vercel 接這個 repo，**Root Directory 留 `./`**（`shared` 是 workspace 相依，必須在 root 安裝），
   環境變數填 `VITE_SERVER_URL=https://xxx.onrender.com`，deploy 拿到 `https://xxx.vercel.app`。
3. 回 Render 填 `CORS_ORIGIN=https://xxx.vercel.app`，重新 deploy。

| 平台 | 變數 | 時機 | 備註 |
|---|---|---|---|
| Vercel | `VITE_SERVER_URL` | **build 時** | 寫死進 bundle，改值要重新 deploy 才生效 |
| Render | `CORS_ORIGIN` | 執行期 | 逗號分隔可多個；設了卻解析不出來源，伺服器會直接不啟動 |
| Render | `PORT` | — | **不要自己設**，Render 會注入 |

其餘（`HOST`、`NODE_VERSION`）由 `render.yaml` 帶入。Render 走 Node 原生 runtime 而不是 Docker，
因為 Render 沒有 `--target` 設定，會建到 Dockerfile 的最後一個 stage（含前端那個）；
Node runtime 下沒有 `client/dist`，後端就只跑 API。

兩件先知道比較好的事：

- **Render free 方案閒置 15 分鐘會停機**，喚醒約 50 秒。狀態全在記憶體，停機一次所有房間與
  牌局歸零，斷線寬限只有 30 秒，玩家一定被踢出座位。要能連著玩就把 `render.yaml` 的
  `plan: free` 改成 `starter`。**每次 deploy 也一樣會清空**，這點付費方案不會變。
- **Vercel 的 preview deployment 連不上後端**：preview 網址是隨機的，白名單是精確比對，
  一律被拒。preview 只驗前端 build 得出來；真要測就把該網址手動加進 `CORS_ORIGIN`。

## 大老二

**牌組**　52 張。點數 `3 < 4 < … < K < A < 2`，花色 `♦ < ♣ < ♥ < ♠`。

**發牌**　不論 2/3/4 人都是每人 13 張，剩下的牌本局不用。
持有 ♣3 的人先手，且第一手必須包含那張牌。人數不足導致 ♣3 沒發出去時，
就以 ♣3 為起點往上找最小的一張當開局牌（繞一圈後才輪到比它更小的 ♦3）。

**牌型**

| 張數 | 牌型 | 比大小 |
| --- | --- | --- |
| 1 | 單張 | 點數 → 花色 |
| 2 | 對子 | 點數 → 較大花色 |
| 3 | 三條 | 點數 |
| 5 | 順子 | 最大張點數 → 花色 |
| 5 | 同花 | 最大張點數 → 花色（需開「同花」） |
| 5 | 葫蘆 | 三條的點數 |
| 5 | 鐵支 | 四張的點數 |
| 5 | 同花順 | 最大張點數 → 花色 |
| 13 | 一條龍 | 3 到 2 各一張（需開「認一條龍」） |

順子範圍是 `3-4-5-6-7` 到 `10-J-Q-K-A`，再加最大的 `J-Q-K-A-2`；不接受 `A-2-3-4-5` 這種跨頭順。
沒有 4 張或 6 張以上的牌型。

**規則開關**　五條規則各自獨立，建房時逐項勾選，中途不會變。
選單上的「台灣規則／一般規則」只是一鍵套用的預設組合，怎麼搭都合法。

| 開關 | 打開時 | 關掉時 | 台灣 | 一般 |
| --- | --- | --- | :-: | :-: |
| 可以切 | 鐵支／同花順／一條龍無視檯面都蓋得過去，彼此間 `一條龍 > 同花順 > 鐵支` | 沒有切，一切照張數與牌型比 | ✔ | ✘ |
| 認一條龍 | 13 張一次出完算一種牌型 | 沒有 13 張的牌型 | ✔ | ✘ |
| 同花 | 合法牌型 | 湊成同花的五張只是散牌 | ✘ | ✔ |
| 五張同型跟 | 只能用**同一種**牌型跟（出順子就只能拿順子接） | 可跨牌型壓，`順子 < 同花 < 葫蘆 < 鐵支 < 同花順` | ✔ | ✘ |
| PASS 鎖整輪 | 退出這一輪，後面再輪也跳過你 | 下一輪輪到你還是能出 | ✔ | ✘ |

沒有勾任何東西時，房間預設就是台灣那一欄。房間標籤只在完全符合某一欄時顯示套組名，
否則顯示「自訂規則」並把開著的規則逐條列在房間標頭。

**回合**　跟牌張數必須一致（「切」除外）。其他人全部 PASS 後，
最後出牌的人取得領牌權，可自由出牌；領牌者不能 PASS。
每回合 45 秒，逾時自動 PASS，有領牌權時改成自動出最小的一組合法牌。

**結束**　手牌先出完的人名次在前，剩最後一人時本局結束。不計分，房主可直接開下一局。

## 德州撲克

2~9 人的**房內現金局**：進房拿 1000 籌碼，盲注 10 / 20。房主開第一手之後就自動接下去 ——
攤牌停留 6 秒發下一手並輪莊，籌碼歸零的人在下一手開始時自動補回 1000，所以牌局不會「結束」。

翻牌前 / 翻牌 / 轉牌 / 河牌四條街，動作是蓋牌／過牌／跟注／加注。
加注一律用「這一街總共加到多少」表示，前後端不會對增量與總量各自解讀。
籌碼不夠加滿最小幅度時仍可以 all-in，但那算短加注，不會重開已表態者的加注權。
邊池依各人這一手的累計投入切分；下不滿的跟注、多人 all-in、跟注跟過頭的退款都算進去。

牌型是標準的高牌／一對／兩對／三條／順子／同花／葫蘆／鐵支／同花順，
七選五取最佳 —— 注意三條／順子／同花／葫蘆這些詞在兩種玩法裡**排序不同**。

## 大富翁

2~6 人，40 格棋盤、28 塊可買的地，起始現金可調（預設 1500）。規則是完整版：

**一回合分成好幾個階段**　擲骰 → 移動結算 → 買或不買 → 整理資產 → 結束回合。
擲出同點可以再擲一次，連三次同點直接進監獄。出獄有三條路：交保 50、用免費出獄卡、
或擲出同點；關滿三巡強制交保。

**地產**　湊齊整個色組才能蓋房，同色組要平均蓋（任兩塊差不超過一棟），第五棟是飯店。
銀行的房屋與飯店有庫存上限（32 / 12），搶完就沒了。素地滿貫租金加倍，蓋了房就照級距。
機場照持有張數收 25/50/100/200，公用事業照持有數收骰子點數的 4 倍或 10 倍。
抵押拿一半價錢、贖回要加一成利息，抵押中的地不收租，且該色組有地在抵押時不能蓋房。

**付不出錢時**　進入償債階段，可以拆房、抵押、跟人交易來湊；真的湊不出來才能宣告破產，
資產全數轉給債主（欠銀行的話土地回無主）。**還付得出來就不准破產**。

**拍賣與交易**　不買的地流入拍賣，繞桌喊價，出價不得超過自己的現金（所以不會有得標付不出的狀況），
不加價就永久退出這場拍賣。交易是指定對象、地產加現金的原子交換，對方接受才成立。

**結束**　三種條件可以各自開關，最先觸發的那個結束本局，名次一律照身家排：
破產淘汰到只剩一人、達到巡數上限、有人先達到身家目標。三個都關掉時會自動補上第一項。

每個階段的秒數不一樣：擲骰／獄中／償債／整理 45 秒，買地與喊價 20 秒，交易 30 秒。
逾時一律有代打，而且**保證會讓局面前進**，不會卡住整桌。

## 貪吃蛇

2~4 人，20×20 格，**唯一的即時制玩法**：沒有輪流，所有蛇每 150ms 同時前進一格。
開局先倒數 3 秒讓大家看清楚出生位置（四個角落各一），時間到才真的開始動。
方向鍵與 WASD 都吃，但按下去只是寫進輸入緩衝，下一拍才套用，180° 迴轉會被忽略；
焦點在聊天框裡時不吃按鍵。

**死亡與重生**　撞牆、撞到任何蛇身（含自己）都算死。每人有兩條命：第一次死掉會在
安全空位重生，原地閃爍 3 秒（幽靈狀態，不參與碰撞），命用完才徹底出局。
同一拍兩顆頭要進同一格、或兩條蛇互穿，雙方這一拍原地不動而不是同歸於盡。

**果實**　場上固定兩顆一般果實，吃到加一分、長一節。另外會輪流生出**帶顏色的地雷果實**：
先閃爍 2 秒預警（這段時間吃不到也害不死人），生效後 5 秒沒人動就自然消失，
消失之後隔 5 秒才生下一顆。本人吃到自己顏色的加 3 分並長一節，別人碰到直接死。

**結束**　名次照分數排，同分時晚出局的排前面。所有人出局就結束；
只剩一人且分數已經追不上任何出局者時提前收尾，不讓他一個人空跑。

## 台灣麻將

固定 4 人的**十六張台灣麻將**。人數不到 4 人時房間會自動補電腦代打，一個人也能整桌試玩；
真人想加入一個已經滿位、但還有電腦座位的房間時，可以送出申請，房主接受後就會頂掉一個電腦、
換真人入座。牌局中途若有真人離開，空出來的座位立刻由電腦接手繼續打，比賽不會因此中斷。

**牌組** 144 張：萬／索／筒各 1~9 每種 4 張（108 張）、東南西北四風各 4 張（16 張）、
中發白三元各 4 張（12 張）、春夏秋冬梅蘭竹菊花牌各 1 張（8 張）。座位 n 摸到對應的
那張春夏秋冬／梅蘭竹菊算「正花」，比別人摸到的花多算一台。摸到的花牌會實際畫在牌桌上——
自己的花牌顯示在手牌上方，其他玩家的花牌顯示在座位小卡片裡，不是只算分數看不到牌。

**動作** 摸牌後可以出牌，或視情況選擇自摸胡／暗槓／加槓；別人打出的牌可以吃（僅限下家）、
碰、槓、胡，選項與合法性一律由伺服器判定。胡牌需要湊滿 5 組面子＋1 對（吃碰槓過的面子算進
5 組裡）。剛摸到的牌會跟手牌分開一格顯示，方便看清楚這一手要不要打出去。

**計台** 簡化版台灣十六張計台表：花牌、正花、自摸、門清、平胡、碰碰胡、清一色／混一色／
字一色、大小三元、大小四喜、自風／圈風、天胡／地胡、槓上開花、海底撈月／河底撈魚、搶槓、
暗刻數、莊家加台都算，沒有台數的胡牌保底算「屁胡」1 台。單一東風場，沒有七對子／十三么等
進階牌型，一手牌若有多種拆法只取其中一種算台，非正式比賽逐字對照版本。

**開局** 房主開始遊戲後先擲 3 秒的骰子（三顆），從 0 號座位起算骰子點數總和決定這局真正的
莊家；擲骰跟接下來蓋牌的 3 秒裡，所有人的手牌都是蓋著的，翻牌顯示「遊戲開始」之後電腦才會
開始動作（多留 0.75 秒緩衝，不會一翻牌電腦就搶著打牌）——莊家每局都可能不同，不是固定第一位。

**結算與下一局** 一局結束（有人胡牌或流局）後，牌桌中央會先顯示獲勝方的牌組，下方接著秀
台數與逐項台數明細，同時公開所有人的手牌（含吃碰槓的面子）讓大家互相核對，牌桌上原本的
棄牌就先收起來。一般局要等所有人按下「繼續」才會開下一局，逾時 3 分鐘沒按到齊也會直接開下
一局，不會把沒按的人踢出房間。每人起始 1000 分，率先到 2000 分或打滿 4 局就是最後一局——
這一局不用等按繼續，結算畫面固定顯示 20 秒後直接公布「恭喜你完成 N 場對局」的最終名次。

## 外觀與隱匿模式

這是拿來上班玩的，所以**沒有任何一句給使用者看的字寫死在元件裡**，全部走當前外觀的文案表。

三套外觀依序循環：`vscode`（預設）、`terminal`、`casino`（原本的牌桌樣子）。
在編輯器外觀裡，點數是檔名、花色是副檔名（`.ts` `.tsx` `.js` `.json`），
四種副檔名本來就有四種顏色，玩家照樣一眼分得出花色，旁人看到的只是一排檔案。

大富翁的棋盤刻意做成**一格一列的清單**，就是為了這個：在編輯器外觀裡它讀起來是 Explorer 的
檔案樹（色組＝目錄、房子＝Problems 徽章），在終端機外觀裡是 `ls -l` 的輸出（色組＝掛載點、
房子＝檔名尾綴的星號）。做成方形棋盤就沒有任何說得過去的偽裝。

| 預設鍵 | 行為 |
| --- | --- |
| `F8` | 循環切換外觀 |
| `F9` | 老闆鍵：整個畫面蓋掉，再按一次還原（只認快捷鍵，滑鼠點不掉） |

另外預設開著「切到別的分頁就自動遮蔽」（延遲 800ms），還可另外打開「滑鼠移出瀏覽器視窗就遮蔽」；
這兩種遮蔽回來就自動解除。分頁標題與 favicon 也跟著外觀換。
遮蔽時畫面只是 `visibility:hidden`，元件不解除掛載 —— socket 與牌局狀態一直活著，回來就是最新畫面。
偏好存在 `localStorage` 的 `ws.prefs`，右下角齒輪可以改。

## 房間、斷線與計時

**身分**　`playerId` 是存在 `sessionStorage` 的 UUID，暱稱存 `localStorage`。
同一個 `playerId` 再連進來，舊的連線會被踢掉。

**斷線**　socket 斷掉只標記離線並保留座位與手牌 30 秒，重連就無縫接回。
離線期間輪到他時把倒數縮到 3 秒後代打，不讓整桌乾等；超過 30 秒才真的移出房間。
貪吃蛇沒有回合也就沒有代打：斷線期間蛇會照最後的方向繼續走，真的被移出房間時直接出局。
中途離開是空出座位而不是把座位往前擠，所以座位編號始終穩定。
房主離開時 host 自動轉給下一位在座玩家，房間空了就解散
（電腦玩家不算「有人在」，全部真人都走了房間一樣會被回收）。
台灣麻將是例外：座位空出來不是等 30 秒後移出，而是立刻由電腦補上繼續打，比賽不會中斷。

**觀戰**　觀戰者是上帝視角，看得到所有人的手牌。
這代表玩家可以自己開第二個分頁觀戰自己那局 —— 想防的話再加「房間密碼／房主可關閉觀戰」即可。

## 架構

```
shared/   規則引擎與型別，前後端共用同一份（零依賴的純 TS）
server/   Express + Socket.IO，房間與遊戲狀態都在記憶體
client/   Vite + React + TypeScript
```

`shared` 是**當原始碼吃的**，不是建置產物：它的 `main` 直接指向 `src/index.ts`，
前端靠 Vite alias 解析，兩邊 tsconfig 也各自 map 過去。沒有任何步驟編譯它。

**規則共用**　`shared/src/combos.ts` 是大老二合法性的唯一出處，
`shared/src/holdem.ts` 是德州撲克牌力與下注合法性的唯一出處，
`shared/src/monopoly.ts` 是棋盤資料與租金／抵押／蓋房算式的唯一出處，
`shared/src/mahjong.ts` 是台灣麻將吃碰槓胡合法性與計台算式的唯一出處。
伺服器拿它做權威判定，前端用**同一份程式碼**即時決定按鈕能不能按、提示要選哪幾張，
所以規則不會前後端各寫一套而走鐘。
大富翁的動作太多也太看情境，所以合法性由伺服器逐觀看者算成 `myActions` 一併送出，
前端只照著長按鈕，一行規則都不重算。
貪吃蛇沒有「合法動作」這回事，`shared/src/snake.ts` 只放棋盤常數與型別，
移動與碰撞全在伺服器的 tick 迴圈裡算，前端純粹畫出每一拍的快照。

**狀態同步**　任何變更後由伺服器重算並推送完整快照，前端不做樂觀更新。
`room:state` 是為每個連線各自產生的：玩家只拿得到自己的手牌（或底牌），其他人只有張數；
觀戰者才拿得到 `allHands`。

**伺服器不送句子**　因為畫面要能偽裝，後端一律只給結構：
牌桌記錄是 `LogEvent[]`、系統訊息帶 `notice`、玩家的上一個動作是 `SeatAction`，
中文句子全部由前端依當前外觀組出來。新增一種記錄就是新增一個 union 成員，
三套外觀的 `formatLog` 會被編譯器逼著補齊。

**分層**　`gameEngine.ts` / `holdemEngine.ts` / `monopolyEngine.ts` 是純函式、不碰 I/O，
是單元測試的對象；`rooms.ts` 管房間與快照組裝；`handlers.ts` 是所有 socket 接線、
計時器與輸入清洗。三個引擎都滿足同一個 `TurnBased` 介面，所以計時器那層不需要為玩法分支。
關鍵在於 `turnSeat` 的定義是「現在該送出動作的座位」而不是「輪到誰」：
大富翁拍賣時它指向喊價者、交易時指向被提議的人，「這一巡是誰的回合」另外記在引擎裡。
因為拍賣與交易都是循序的，任何時刻都只有一個座位待輸入，房間層才能完全不必知道差別。

更動程式碼前請先看 `CLAUDE.md`，那裡有「要加一條規則／一個事件時該動哪幾個檔」的清單。
